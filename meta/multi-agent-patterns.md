# 🤖 Multi-Agent Patterns — Паттерны мульти-агентных систем

**Источник:** [Six Core Design Principles for Multi-AI Agent Systems](https://cobusgreyling.substack.com/p/six-core-design-principles-for-multi)

---

## 📋 Обзор

Шесть основных паттернов проектирования для мульти-агентных систем на базе LLM:

1. **Flow Control** — Управление потоком
2. **Interaction Styles** — Стили взаимодействия
3. **History Sharing** — Обмен историей
4. **Network Configurations** — Конфигурации сети
5. **Human Interaction** — Взаимодействие с человеком
6. **ReAct Workflow** — Рабочий процесс агента

---

## 1. Flow Control — Управление потоком

### Варианты

| Тип | Описание | Когда использовать |
|-----|----------|-------------------|
| **Явный (Explicit)** | Предопределённые последовательности, графы, оркестрируемые рабочие процессы | Когда требуется предсказуемость и аудит |
| **Динамический (LLM-driven)** | Решения принимаются LLM во время выполнения | Когда нужна гибкость и адаптивность |

### Пример: Явный поток (kk-userator)

```
User → Coordinator → Analyst → Reviewer → Architect → Reviewer → Engineer → Reviewer → Done
```

**Преимущества:**
- ✅ Предсказуемость
- ✅ Легче отладка
- ✅ Явные точки контроля

**Недостатки:**
- ❌ Меньше гибкости
- ❌ Не адаптируется к сложным сценариям

### Пример: Динамический поток

```
User → [LLM решает] → Analyst или Engineer → [LLM решает] → ...
```

**Преимущества:**
- ✅ Адаптивность
- ✅ Пропускает ненужные этапы

**Недостатки:**
- ❌ Стохастическое поведение
- ❌ Сложнее отладка

## 2. Interaction Styles — Стили взаимодействия

### Handoff (Передача промптов)

```
Agent A → [передаёт контекст] → Agent B → [передаёт контекст] → Agent C
```

**Когда использовать:**
- Простые цепочки задач
- Агенты работают последовательно
- Минимум инструментов

### Tool Flow / Function Calling

```
                    ┌──────────────┐
                    │  Coordinator │
                    └──────┬───────┘
                           │
         ┌─────────────────┼─────────────────┐
         │                 │                 │
         ▼                 ▼                 ▼
   ┌──────────┐    ┌──────────┐    ┌──────────┐
   │ Analyst  │    │ Engineer │    │ Reviewer │
   └──────────┘    └──────────┘    └──────────┘
```

**Когда использовать:**
- Сложные системы с инструментами
- Параллельное выполнение
- Координация через супервизора

## 3. History Sharing — Обмен историей

### Полный трассировочный след

```
Agent A: [Thought, Action, Observation] → Agent B: [Thought, Action, Observation]
              │                                    │
              └───────────> Shared Log <───────────┘
```

**Когда использовать:**
- Отладка и аудит
- Обучение агентов
- Комплаенс требования

**Преимущества:**
- ✅ Полная прозрачность
- ✅ Легче найти ошибку

**Недостатки:**
- ❌ Большой расход токенов
- ❌ Медленнее работа

### Только финальные результаты

```
Agent A: [Result] → Agent B: [Result]
```

**Когда использовать:**
- Эффективность важнее прозрачности
- Приватность внутренних шагов
- Ограниченный контекст

## 4. Network Configurations — Конфигурации сети агентов

### Супервизор (Supervisor)

```
              ┌─────────────┐
              │ Supervisor  │
              └──────┬──────┘
                     │
        ┌────────────┼────────────┐
        │            │            │
        ▼            ▼            ▼
   ┌────────┐  ┌────────┐  ┌────────┐
   │ Leaf 1 │  │ Leaf 2 │  │ Leaf 3 │
   └────────┘  └────────┘  └────────┘
```

**kk-userator использует эту конфигурацию**

**Когда использовать:**
- Чёткое разделение ответственности
- Централизованная координация
- Иерархическая структура

### Рой (Swarm)

```
   ┌──────┐    ┌──────┐
   │ A1   │◄──►│ A2   │
   └──┬───┘    └──┬───┘
      │           │
      └─────┬─────┘
            │
         ┌──────┐
         │ A3   │
         └──────┘
```

**Когда использовать:**
- Децентрализованное принятие решений
- Агенты равноправны
- Handoffs между агентами

### Иерархическая

```
         ┌──────────────┐
         │ Top Manager  │
         └──────┬───────┘
                │
        ┌───────┴───────┐
        │               │
   ┌────▼────┐    ┌────▼────┐
   │ Manager │    │ Manager │
   └────┬────┘    └────┬────┘
        │               │
   ┌────┴────┐    ┌────┴────┐
   │Leaf │Leaf│    │Leaf │Leaf│
   └─────┴─────┘    └─────┴─────┘
```

**Когда использовать:**
- Сложные организации
- Много уровней абстракции
- Масштабирование

### Единая информационная среда (SIE)

```
   ┌──────┐     ┌──────┐
   │ A1   │     │ A2   │
   └──┬───┘     └──┬───┘
      │            │
      └─────┬──────┘
            │
      ┌─────▼─────┐
      │   SIE     │
      │  (Router) │
      └─────┬─────┘
            │
      ┌─────▼─────┐
      │   A3      │
      └───────────┘
```

**Когда использовать:**
- Разнородные источники данных
- Динамическая маршрутизация
- Общие данные между агентами

## 5. Human Interaction — Взаимодействие с человеком

### Human-in-the-loop

```
Agent → [Решение] → Human → [Approve/Reject] → Agent
```

**Когда использовать:**
- Критические решения
- Высокие риски
- Юридические требования

**Пример в kk-userator:**
- Чекпоинты после каждого этапа
- Пользователь утверждает перед переходом к следующему этапу

### Human-on-the-loop

```
Agent → [Действие] → Human → [Monitor only]
```

**Когда использовать:**
- Низкие риски
- Автоматизация рутинных задач
- Надзор без вмешательства

## 6. ReAct Workflow — Рабочий процесс агента

### Цикл ReAct

```
┌─────────────────────────────────────────────┐
│            ReAct Agent Loop                 │
└─────────────────────────────────────────────┘

     ┌─────────┐
     │ Thought │  (Что я знаю? Что нужно сделать?)
     └────┬────┘
          │
          ▼
     ┌─────────┐
     │ Action  │  (Вызов инструмента, API, функции)
     └────┬────┘
          │
          ▼
     ┌─────────────┐
     │ Observation │  (Результат действия)
     └────┬────────┘
          │
          ▼
     [Повторить или Завершить]
```

**Пример:**

```
Thought: Мне нужно создать пользователей в Keycloak.
         Сначала проверю доступность API.

Action: keycloak_admin.get_version()

Observation: {"version": "23.0.1"}

Thought: API доступно. Теперь создам группу.

Action: keycloak_admin.create_group({"name": "engforinclusb-users"})

Observation: {"id": "abc123", "name": "engforinclusb-users"}

Thought: Группа создана. Теперь создам пользователей.
...
```

**Когда использовать:**
- Индивидуальные агенты
- Задачи с инструментами
- Итеративное решение проблем

## 📊 Сравнение конфигураций

| Конфигурация | Сложность | Масштабируемость | Гибкость | Отладка |
|--------------|-----------|------------------|----------|---------|
| Супервизор | Низкая | Средняя | Низкая | Легко |
| Рой | Средняя | Высокая | Высокая | Сложно |
| Иерархическая | Высокая | Высокая | Средняя | Сложно |
| SIE | Высокая | Очень высокая | Очень высокая | Очень сложно |

## 🎯 Применение в kk-userator

| Паттерн | Текущая реализация | Потенциальные улучшения |
|---------|-------------------|------------------------|
| **Flow Control** | Явный (Coordinator управляет) | Добавить динамический для простых задач |
| **Interaction** | Tool Flow (супервизор + листовые агенты) | ✅ Оптимально |
| **History** | Полный след (activity.log) | ✅ Оптимально с маркировкой доверия |
| **Network** | Супервизор | Рассмотреть SIE для масштабирования |
| **Human** | In-the-loop (чекпоинты) | ✅ Оптимально для критичных задач |
| **ReAct** | Встроен в агентов | ✅ Оптимально |
