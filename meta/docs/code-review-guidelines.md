# 🔍 Code Review — Спецификация процесса

**Источники:** GitLab Code Review Guidelines, GitHub Docs

---

## 📋 Назначение

**Код-ревью** — проверка изменений кода перед слиянием в основную ветку.

**Функция:**
```
PR (изменения) + Reviewer → [Проверка по чеклисту] → Статус (Approve/Request Changes/Comment)
```

---

## 🔄 Процесс

```
┌─────────────────────────────────────────────────────────────────┐
│                    Code Review Process                          │
└─────────────────────────────────────────────────────────────────┘

  Engineer                        Reviewer
    │                               │
    │  [1] Создать PR               │
    │──────────────────────────────►│
    │                               │
    │                               │ [2] Проверка по чеклисту
    │                               │
    │                               │ [3] Статус + комментарии
    │◄──────────────────────────────│
    │                               │
    │  [4a] Исправления (если нужно)│
    │──────────────────────────────►│
    │                               │
    │                               │ [5] Повторная проверка
    │◄──────────────────────────────│
    │                               │
    │                               │ [6] Approve
    │──────────────────────────────►│
    │                               │
    │  [7] Мерж                     │
    │                               │
```

## ✅ Чеклист проверки

### Функциональность
- [ ] Код соответствует требованиям PR
- [ ] Логика корректна
- [ ] Краевые случаи обработаны
- [ ] Нет регрессий

### Качество кода
- [ ] Код читаем
- [ ] Нет дублирования
- [ ] Функции/классы имеют одну ответственность
- [ ] Имена понятны

### Безопасность
- [ ] Нет уязвимостей (инъекции, XSS, CSRF)
- [ ] Валидация входных данных
- [ ] Нет секретов в коде
- [ ] Авторизация проверена

### Производительность
- [ ] Нет узких мест
- [ ] Запросы оптимизированы
- [ ] Нет утечек памяти

### Тесты
- [ ] Тесты покрывают изменения
- [ ] Тесты проходят
- [ ] Нет нестабильных тестов

## 📊 Статусы ревью

| Статус | Значение | Триггер |
|--------|----------|---------|
| **Approve** | Готово к мержу | Все чеклисты ✅ |
| **Request Changes** | Требуются исправления | Есть блокирующие замечания |
| **Comment** | Вопросы без блокировки | Есть рекомендации/вопросы |

---

## 🏷️ Типы комментариев

### 1. Блокирующие (Blockers)
```
❌ "Критичная уязвимость безопасности"
❌ "Логика неверна"
```
**Действие:** Требует исправления перед мержем.

### 2. Рекомендации (Suggestions)
```
⚠️ "Вынести в отдельную функцию"
⚠️ "Использовать list comprehension"
```
**Действие:** Опционально, улучшает код.

### 3. Вопросы (Questions)
```
❓ "Почему выбрано это значение?"
❓ "Есть ли причина не использовать метод X?"
```
**Действие:** Требует пояснения от автора.

## ⚠️ Ошибки

### Инженер
| Ошибка | Последствие |
|--------|-------------|
| Огромный PR (>1000 строк) | Пропуск багов |
| Нет описания PR | Непонятен контекст |
| Игнорирование комментариев | Баги в коде |

### Ревьюер
| Ошибка | Последствие |
|--------|-------------|
| Поверхностное ревью | Баги проходят |
| Микроменеджмент | Блокировка без причины |
| Пропуск чеклиста | Неполная проверка |

---

## 📏 Метрики

| Метрика | Порог |
|---------|-------|
| Размер PR | < 400 строк |
| Время ревью | < 24 часов |
| Комментарии на PR | 5-15 |
