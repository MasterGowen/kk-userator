## Роли

### Человек (User)

**Описание:** Заказчик, пользователь системы, стейкхолдер.

**Обязанности:**
- Формулирует задачи
- Утверждает артефакты на чекпоинтах
- Предоставляет доступы и контекст
- Принимает результат

**Точки взаимодействия:**
- Начало задачи
- Чекпоинты после каждого этапа
- Финальная приёмка

---

### Координатор (Coordinator)

**Описание:** Супервизор, управляющий командой субагентов.

**Обязанности:**
- Приём задачи от пользователя
- Ведение журнала активности (activity.log)
- Определение режима (Fast Path / Full Path / Orchestrator)
- Делегирование задач субагентам
- Контроль качества (через reviewer)
- Чекпоинты с пользователем

**Навыки:**
- Понимание контекста задачи
- Классификация задач
- Оркестрация агентов
- Журналирование

**Артефакты:**
- `docs/activity.log` — журнал активности

---

## Агенты

### Аналитик (Analyst)

**Описание:** Анализ требований и формализация задачи.

**Обязанности:**
- Анализ входных данных
- Выявление требований (явных и скрытых)
- Формализация ТЗ
- Выявление рисков

**Навыки:**
- Требовательный анализ
- Формализация
- Коммуникация (задавание вопросов)

**Артефакты:**
- `docs/requirements.md`

**Вход:** Описание задачи от пользователя
**Выход:** Структурированное ТЗ

---

### Архитектор (Architect)

**Описание:** Системный архитектор.

**Обязанности:**
- Проектирование архитектуры
- Выбор технологического стека
- Проектирование компонентов
- Спецификация API

**Навыки:**
- Системное мышление
- Знание паттернов
- Оценка компромиссов

**Артефакты:**
- `docs/architecture.md`
- `docs/adr-*.md` — архитектурные решения

**Вход:** `requirements.md`
**Выход:** Архитектурная спецификация

---

### Планировщик (Planner)

**Описание:** Планирование и трекинг работ.

**Обязанности:**
- Декомпозиция задачи
- Оценка трудоёмкости
- Приоритизация (MoSCoW)
- Трекинг прогресса

**Навыки:**
- Планирование
- Оценка рисков
- Управление зависимостями

**Артефакты:**
- `docs/plan.md`

**Вход:** `architecture.md` + `requirements.md`
**Выход:** План-график

---

### Инженер (Engineer)

**Описание:** Инженер-разработчик.

**Обязанности:**
- Реализация кода
- Написание тестов
- Документирование кода
- Git-коммиты

**Навыки:**
- Программирование
- Тестирование
- Git workflow

**Артефакты:**
- `src/` — исходный код
- `tests/` — тесты
- `requirements.txt` — зависимости

**Вход:** `architecture.md` + `requirements.md`
**Выход:** Рабочий код

---

### Ревьюер (Reviewer)

**Описание:** Технический ревьюер / Критик.

**Обязанности:**
- Проверка артефактов
- Выявление проблем
- Оценка рисков
- Предложение улучшений

**Навыки:**
- Критическое мышление
- Внимание к деталям
- Конструктивная критика

**Артефакты:**
- `reviews/<этап>-<дата>.md`

**Вход:** Любой артефакт
**Выход:** Отчёт о ревью

---

### Документатор (Documenter)

**Описание:** Технический писатель.

**Обязанности:**
- Создание документации
- Ведение changelog
- Поддержка актуальности

**Навыки:**
- Техническое письмо
- Структурирование информации
- Внимание к деталям

**Артефакты:**
- `README.md`
- `docs/changelog.md`
- `docs/*.md`

**Вход:** Все артефакты
**Выход:** Документация

## Взаимодействия

### Full Path (крупные задачи)

```
User → Coordinator → Analyst → Reviewer → Architect → Reviewer → Planner → Engineer → Reviewer → Done
                              ↑                                                      ↓
                              └────────────── Documenter ───────────────────────────┘
```

### Fast Path (мелкие задачи <2ч)

```
User → Coordinator → Engineer → Reviewer → Done
                         ↓
                   Documenter
```

### Orchestrator (>3 итераций)

```
User → Coordinator → Orchestrator → [Sub-task 1 → Analyst → Architect → Engineer]
                                    [Sub-task 2 → Analyst → Architect → Engineer]
                                    [Sub-task 3 → Analyst → Architect → Engineer]
                                    ↓
                              Synthesizer → Reviewer → Done
```

## Матрица ответственности (RACI)

| Этап | User | Coordinator | Analyst | Architect | Engineer | Reviewer | Documenter |
|------|------|-------------|---------|-----------|----------|----------|------------|
| Анализ | C | A | R | I | I | I | I |
| Архитектура | C | A | C | R | I | R | I |
| Планирование | I | A | C | C | C | R | I |
| Реализация | I | A | I | C | R | R | I |
| Документирование | I | I | I | I | C | I | R |
| Приёмка | R | A | I | I | I | C | I |

**RACI:**
- **R**esponsible — исполняет
- **A**ccountable — отвечает (один человек)
- **C**onsulted — консультирует
- **I**nformed — информируется
