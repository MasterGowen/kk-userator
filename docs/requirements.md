# Техническое задание: Генерация учётных записей для курса «Английский для лиц с нарушениями зрения»

**Дата:** 2026-03-18 (ред. 3 — утверждено)
**Проект:** kk-userator
**Статус:** ✅ Готово к реализации

---

## 1. Резюме задачи

Необходимо создать 200 учётных записей в системе Keycloak для последующей апробации курса «Английский для лиц с нарушениями зрения» в рамках диссертационного исследования. Учётные записи должны иметь последовательную нумерацию (1–200) и уникальные пароли. Интеграция Keycloak → OpenEDX (Tutor) настроена: учётные записи в OpenEDX создаются автоматически при первом входе пользователя через Keycloak.

## 3. Функциональные требования

1. **ФР-1.** Система должна создавать учётные записи в Keycloak в количестве 200 штук.

2. **ФР-2.** Имена пользователей (логин) должны формироваться по шаблону: `enginc_1, enginc_2, enginc_3... enginc_200` где:
   - `eng` — English (английский язык)
   - `inc` — inclusive (инклюзивный)
   - `_` — разделитель
   - `1–200` — порядковый номер пользователя

3. **ФР-3.** Каждая учётная запись должна иметь уникальный пароль.

4. **ФР-4.** Пароли должны соответствовать политике безопасности Keycloak (минимальная длина, сложность) — **требуется уточнение текущей политики**.

5. **ФР-5.** Система должна сохранять сгенерированные учётные данные (логин + пароль) в машиночитаемом формате (CSV/JSON/XLSX).

6. **ФР-6.** Система должна поддерживать идемпотентность: повторный запуск не должен создавать дубликаты учётных записей.

7. **ФР-7.** Учётные записи должны быть активированы сразу после создания (статус: Enabled).

8. **ФР-8.** Учётные записи должны быть привязаны к нужному realm в Keycloak — **требуется уточнение имени realm**.

---

## 4. Нефункциональные требования

1. **НФР-1.** Время создания 200 учётных записей не должно превышать 5 минут.

2. **НФР-2.** Решение должно быть воспроизводимым: возможность повторного запуска на другом окружении при наличии доступа к Keycloak API.

3. **НФР-3.** Хранение паролей: сгенерированные пароли должны храниться в защищённом месте с ограниченным доступом.

4. **НФР-4.** Логирование: процесс создания учётных записей должен протоколироваться с указанием статуса каждой операции (успех/ошибка).

5. **НФР-5.** Безопасность: скрипт/инструмент не должен хранить учётные данные администратора Keycloak в открытом виде (использовать переменные окружения).

6. **НФР-6.** Масштабируемость: решение должно допускать создание другого количества учётных записей через параметр запуска.

## 5. Критерии приёмки (DoD)

### 5.1. Обязательные критерии

- [ ] Создано ровно 200 учётных записей в Keycloak
- [ ] Все учётные записи имеют статус «Enabled»
- [ ] Логин каждой учётной записи соответствует заданному шаблону (последовательный номер)
- [ ] Каждая учётная запись имеет уникальный пароль
- [ ] Сгенерирован файл с учётными данными (логин + пароль) в формате CSV/JSON/XLSX
- [ ] Файл с паролями доступен только авторизованным лицам

### 5.2. Проверка работоспособности

- [ ] Минимум 5 случайных учётных записей прошли тестовый вход через Keycloak → OpenEDX
- [ ] При первом входе пользователя учётная запись корректно создаётся в OpenEDX автоматически
- [ ] Повторный запуск скрипта не создаёт дубликатов
